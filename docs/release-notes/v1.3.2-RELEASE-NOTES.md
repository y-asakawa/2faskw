# 2FAS-KW v1.3.2 リリースノート

## 1. 概要

v1.3.2は、配布物の利用手順とログ保持運用を整理する運用改善リリースである。
認証フロー、GraphicalMatrix enrollment、DB schema、SP管理台帳、属性カタログ、
SP別アクセス制御、MFA方針の機能変更は含まない。

## 2. 主な変更

| 項目 | 内容 | 既存環境への影響 |
| --- | --- | --- |
| 配布物の文書 | 詳細な`docs/`をPluginおよびAdmin Tools配布物から除外した。トップレベル`README.md`からGitHub上の正本を案内する。 | 既存のIdP設定・Admin Tools設定は変更しない。 |
| Admin Tools installer | Admin Tools配布物に含まれない`docs/`をインストール先へコピーしない。 | 既存の`/opt/graphicalmatrix-admin/docs`は削除しない。 |
| logrotateサンプル | `examples/logrotate/`に2FAS-KW固有ログのサンプルを集約した。 | OSの`/etc/logrotate.d/`は自動変更しない。必要な環境だけ手作業で配置する。 |
| パッケージ検査 | PluginおよびAdmin Toolsパッケージに必要なlogrotateサンプルが含まれることを検査する。 | 配布物の検証範囲が増える。 |

## 3. logrotateサンプル

Plugin配布物には次のサンプルを含む。

```text
examples/logrotate/README.md
examples/logrotate/graphicalmatrix-audit
examples/logrotate/graphicalmatrix-sp-management-audit
examples/logrotate/graphicalmatrix-access-audit
examples/logrotate/graphicalmatrix-csv-import
```

Admin Tools配布物には、CSVプロビジョニングに必要な次の2ファイルだけを含む。

```text
examples/logrotate/README.md
examples/logrotate/graphicalmatrix-csv-import
```

各サンプルは、日次ローテーション、180世代保持、gzip圧縮、`copytruncate`を使用する。
ログごとに保持期間を変更できるよう、設定ファイルは分離している。使用していない機能の
サンプルを配置する必要はない。

既存の`graphicalmatrix-audit`設定をv1.3.2の内容へ更新する場合は、次を実行する。

```bash
sudo install -m 0644 examples/logrotate/graphicalmatrix-audit \
  /etc/logrotate.d/graphicalmatrix-audit

sudo logrotate -d /etc/logrotate.d/graphicalmatrix-audit
```

`copytruncate`を使うため、v1.3.2のサンプルでは`create`および`su`を指定しない。
logrotateはroot実行を前提とし、IdP標準ログと共有する`/opt/shibboleth-idp/logs`の
ディレクトリ所有者を変更してはならない。

## 4. Shibboleth IdP標準ログ

次のShibboleth IdP標準ログは、`/opt/shibboleth-idp/conf/logback.xml`のLogback設定が
日次ローテーションと`idp.loghistory`による保持を管理する。

```text
idp-process.log
idp-warn.log
idp-audit.log
idp-consent-audit.log
idp-password-audit.log
```

標準構成の`idp.loghistory`既定値は180である。これらのログへ2FAS-KWのlogrotateサンプルを
追加適用してはならない。二重ローテーションとなる。

## 5. v1.3.1からの更新

v1.3.1からv1.3.2への更新では、DB migrationおよび設定値の変更は不要である。
通常のPlugin更新後、旧`2faskw-idp-plugin-1.3.1.jar`だけを削除し、
WAR再構築、Jetty再起動、設定検査、既存認証の回帰試験を実施する。

SP管理、属性カタログ、アクセス制御、MFA方針、LDAP Resolverを使用している環境でも、
更新だけで`--apply`を伴うCLI操作を行う必要はない。

詳細な更新手順は[UPGRADE.md](../UPGRADE.md#v131からv132への更新手順)、
logrotateの適用と確認は[LOGROTATE.md](../LOGROTATE.md)を参照する。
