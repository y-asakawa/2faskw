# v1.3.1 SP・IdP全体MFA方針管理CLI

## 1. 目的

v1.3.1では、SP管理CLIが従来から持つSP単位の`set-mfa`を継承し、IdP全体のMFA方針を
管理する`mfa`コマンドを追加する。SP単位設定とIdP全体設定を同じCLIから確認・変更し、
`mfa-policy.properties`の手作業編集による台帳との不整合を防止することが目的である。

本機能はローカル管理CLIであり、HTTP API、管理Web UI、外部公開listenerを追加しない。
適用対象は次のファイルである。

```text
/opt/shibboleth-idp/conf/graphicalmatrix/mfa-policy.properties
```

## 2. 互換性と初期状態

- 既存SPのMFA profileとIdP全体設定は、アップグレードだけでは変更しない。
- `set-mfa`を実行しなければ、SP登録時に指定した`--mfa`が維持される。
- SP追加時に`--mfa`を省略した場合のprofileは`inherit`である。
- `inherit`は無条件のMFA必須を意味せず、IdP全体の評価順に従う。
- IdP全体の既定値は`default=require`である。
- 既定の評価順は次のとおりである。

```text
forceSPs,bypassSPs,bypassSpCidrs,bypassNetwork,requiredSPs,default
```

- 既定の送信元IP・CIDR例外は空である。
- 設定適用後は次の認証から読み込まれ、Jetty再起動は不要である。

## 3. SP単位の`set-mfa`

`SP_NAME`にはentityIDやmetadata provider IDではなく、`list`の`NAME`列に表示される
CLI管理名を指定する。1件のSPには1つのprofileだけを割り当て、再実行時は以前のprofileを置き換える。

```bash
# CLI管理SPの名前と現在のprofileを確認する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh list

# 対象SPをIdP全体方針に従わせる変更予定を確認し、確認後に適用する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh set-mfa SP_NAME inherit
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh set-mfa SP_NAME inherit --apply

# 対象SPでMFAを強制する変更予定を確認し、確認後に適用する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh set-mfa SP_NAME force
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh set-mfa SP_NAME force --apply

# 対象SP全体でMFAを不要にする。dry-runとapplyの両方で明示確認する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh set-mfa SP_NAME bypass \
  --confirm-bypass
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh set-mfa SP_NAME bypass \
  --confirm-bypass --apply

# 対象SPをMFA必須SPの選択リストへ追加する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh set-mfa SP_NAME required
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh set-mfa SP_NAME required --apply

# 対象SPと指定IPv4 CIDRの両方が一致した場合だけMFAを不要にする。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh \
  set-mfa SP_NAME sp-cidr-bypass --cidrs '192.168.10.0/24,10.20.0.0/16'
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh \
  set-mfa SP_NAME sp-cidr-bypass --cidrs '192.168.10.0/24,10.20.0.0/16' --apply
```

profileの意味は次のとおりである。

| profile | 動作 |
| --- | --- |
| `inherit` | SPをSP別ルールから外し、IdP全体方針で判定する。 |
| `force` | 対象SPを`forceSPs`へ登録する。既定順序では送信元CIDR例外より先にMFA必須となる。 |
| `bypass` | 対象SPを`bypassSPs`へ登録し、MFAを不要にする。 |
| `required` | 対象SPを`requiredSPs`へ登録する。リスト外SPがMFA不要になる可能性がある。 |
| `sp-cidr-bypass` | 対象SPと`--cidrs`の両方が一致した場合だけMFAを不要にする。 |

`required`を1件でも設定すると、`requiredSPs`ルール到達時に、リストへ登録していないSPは
MFA不要と判定される。全SPをMFA必須にしたい環境で、新規SPのMFAを有効にするだけの目的では
`required`を使用しない。通常は`inherit`または`force`を使用する。

## 4. IdP全体の`mfa`

### 4.1 現在値と実効判定

```bash
# IdP全体設定、SP別設定、手作業差分の有無を確認する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh mfa show

# 指定したCLI管理SPと送信元IPの最終判定、および判定したルールを確認する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh mfa test \
  --sp SP_NAME --ip 192.0.2.10
```

`mfa show`は`default`、`policy_order`、`bypass_ips`、`bypass_cidrs`、
`use_forwarded_for`、`managed_policy_drift`と、CLI管理SPごとのprofileを表示する。
`mfa test`は設定を変更せず、実際の評価順を使って`REQUIRE`または`BYPASS`と一致ルールを表示する。

### 4.2 IdP全体設定の変更

`mfa global set`で変更できる項目は次のとおりである。

| オプション | 内容 |
| --- | --- |
| `--default require\|bypass` | どの先行ルールにも一致しない場合の既定判定。 |
| `--policy-order RULES` | 6ルールの評価順。各ルールを1回含め、`default`を最後にする。 |
| `--bypass-ips ADDRESSES` | 全SPを判定対象とする送信元IPv4アドレス例外。 |
| `--bypass-cidrs CIDRS` | 全SPを判定対象とする送信元IPv4 CIDR例外。 |
| `--clear-bypass-ips` | 既存の送信元IP例外をすべて削除する。 |
| `--clear-bypass-cidrs` | 既存の送信元CIDR例外をすべて削除する。 |

未指定項目は現在値を保持する。空文字による削除は受け付けず、削除専用オプションを必要とする。

```bash
# 変更後の全設定とplan_sha256を確認する。ファイルは変更しない。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh mfa global set \
  --default require \
  --policy-order 'forceSPs,bypassSPs,bypassSpCidrs,bypassNetwork,requiredSPs,default' \
  --bypass-cidrs '192.168.0.0/16,10.0.0.0/8'

# 同じ値と確認済みplan_sha256を指定して適用する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh mfa global set \
  --default require \
  --policy-order 'forceSPs,bypassSPs,bypassSpCidrs,bypassNetwork,requiredSPs,default' \
  --bypass-cidrs '192.168.0.0/16,10.0.0.0/8' \
  --confirm-bypass \
  --approve-sha256 PLAN_SHA256 \
  --apply

# 既存のCIDR例外を削除する予定を確認する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh mfa global set \
  --clear-bypass-cidrs
```

`default=require`から`bypass`への変更、評価順の変更、IP/CIDR例外の追加はMFAを弱める可能性があるため、
apply時に`--confirm-bypass`を必要とする。applyはdry-runが表示した完成後ファイルの
`plan_sha256`と完全一致する`--approve-sha256`を必要とする。

## 5. 手作業差分の検出と修復

CLI管理SPに対応する`forceSPs`、`bypassSPs`、`requiredSPs`、`bypassSpCidrs`を手作業で変更すると、
`mfa show`は`managed_policy_drift=MISMATCH`を表示する。台帳と方針ファイルが不一致の間は、
該当行を再生成するSP管理操作を停止する。

手作業値を正として自動取り込みは行わない。正しいSP単位方針を`set-mfa`で設定し直すか、
次のコマンドでSP管理台帳の状態へ復元する。

```bash
# 台帳から復元する内容とplan_sha256を確認する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh \
  mfa reconcile --from-registry

# 確認済みの内容を適用する。IdP全体設定は保持する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh \
  mfa reconcile --from-registry \
  --approve-sha256 PLAN_SHA256 \
  --apply
```

## 6. 安全性とファイル管理

- dry-runを既定とし、`--apply`を指定するまでファイルを変更しない。
- IdP全体変更と差分修復は、完成後ファイルのSHA-256による内容承認を必要とする。
- MFAを弱める変更には`--confirm-bypass`を必要とする。
- 設定値を正規化してから検証し、大文字・空白による確認回避を許可しない。
- 変更前のファイルをSP管理transaction backupへ保存する。
- 一時ファイルからのatomic replaceを使用する。
- 書込み後に設定を再検証し、失敗した場合は変更前のファイルへ復元する。
- `mfa-policy.properties`のmodeを`0640`、groupを`graphicalmatrix.sp.runtimeGroup`へ設定する。
- 操作結果を`/opt/shibboleth-idp/logs/graphicalmatrix-sp-management-audit.log`へ記録する。
- IdP全体設定の変更時も、CLI管理SPのprofileと手作業で管理される非CLI SPの設定を保持する。

backupは次のディレクトリへ保存し、次回の更新操作開始時に保持期限を超えたtransactionを削除する。
既定の保持期間は30日である。

```text
/opt/shibboleth-idp/credentials/graphicalmatrix/sp-management-backups
```

## 7. 推奨する適用手順

1. `list`でCLI管理名と現在のSP profileを確認する。
2. `mfa show`でIdP全体設定と`managed_policy_drift`を確認する。
3. `set-mfa`または`mfa global set`をdry-runで実行する。
4. 変更後の全項目、影響するSP、`plan_sha256`を確認する。
5. 必要な確認オプションを付けてapplyする。
6. `mfa show`で保存結果を確認する。
7. CIDR内外の代表IPを指定した`mfa test`で実効判定を確認する。
8. 検証用SPで実際にログインし、IdPログのMFA policy decisionを確認する。

```bash
sudo grep -E 'MFA (policy decision|method decision)' \
  /opt/shibboleth-idp/logs/idp-process.log | tail -n 30
```
