# 2FAS-KW v1.3.4 Security Header Hardening 詳細設計

実装状態: 実装済み

## 1. 文書の目的

本書は、認証済み画面を対象に実施したセキュリティスキャンで確認されたsecurity header不足に対し、
2FAS-KW v1.3.4で実装する防御と互換性要件を定義する詳細設計兼リリースノートである。

対象は次の2件である。

1. Shibboleth IdP内の2FAS-KW servletへ共通security header Filterを追加する。
2. ローカルtest SPのApache/PHP応答headerを強化する。

本書は実装済みの設計と互換性要件を記録する。導入時は`INSTALL.md`、更新時は`UPGRADE.md`、
設定値は`CONFIG-REFERENCE.md`の確定手順を使用する。

## 2. 対象バージョン

本変更の配布対象はv1.3.4とする。

v1.3.3はレスポンシブレイアウト対応としてすでに公開済みのimmutable tagである。公開済みtagを移動、
再作成または同名成果物で置換してはならない。v1.3.3を基点に実装する場合でも、security header hardeningを
含む成果物はv1.3.4として作成する。

## 3. 背景

診断では認証画面とローカルtest SPについて主に次の不足が確認された。

- `Content-Security-Policy`がない、または対象画面に対して十分に制限されていない。
- clickjackingを防ぐ`frame-ancestors`または`X-Frame-Options`がない。
- `X-Content-Type-Options: nosniff`がない。
- 認証URLを外部へ送らない`Referrer-Policy`がない。
- 不要なbrowser capabilityを停止する`Permissions-Policy`がない。
- 認証結果や属性値を保存させないcache policyが応答経路ごとに統一されていない。
- ローカルtest SPが`X-Powered-By`でPHP version情報を返し得る。

現行2FAS-KWは一部servletで`Cache-Control`を個別設定しているが、全応答へ一貫して適用する共通Filterは
存在しない。また、HTML rendererとfallback rendererにはinline JavaScript、inline style、`style`属性がある。
この状態で厳格なCSPだけを追加すると、画像選択、reset、確認dialog、grid列数などが動作しなくなる。

したがって本変更では、header追加とCSP互換化を同一releaseで行う。

## 4. Security invariant

実装後は次の条件を常に満たす。

- 2FAS-KWの認証、自己管理、完了、error画面は第三者originのframe内で表示できない。
- browserは2FAS-KW応答のcontent typeを推測しない。
- 2FAS-KW HTMLは同一originの外部scriptと外部styleだけを実行する。
- scriptに`unsafe-inline`、`unsafe-eval`、wildcard sourceを許可しない。
- 認証・自己管理formの送信先は同一originに限定する。
- 認証URL、query parameter、flow keyをRefererとして外部へ送信しない。
- 認証結果、error、管理API応答、属性確認画面をbrowserまたは中間cacheへ保存させない。
- CSS、JavaScript、画像assetの既存cache policyをFilterが破壊しない。
- Shibboleth標準のSAML POST formへ2FAS-KW固有CSPを適用しない。
- SimpleSAMLphp標準画面へローカルtest application固有CSPを適用しない。
- HTTP/TLS終端構成をservletが推測してHSTSを誤配信しない。
- Filter無効化またはCSP report-only運用は設定検査で可視化する。

## 5. 対象範囲

### 5.1 対象

- `/graphicalmatrix/*`配下の2FAS-KW servlet応答
- `/graphicalmatrix-admin/api/v1/*`配下の管理API応答
- 2FAS-KWのHTML templateとJavaScript/CSS asset
- `graphicalmatrix-plugin-webxml.sh`が管理するFilter定義とmapping
- `graphicalmatrix.properties`のsecurity header設定
- `graphicalmatrix-plugin-check.sh --config-only`による設定検査
- `local-unattended-install.sh`が生成するローカルtest SP
- `local-unattended-SP-install.sh`が生成するSP-only test環境
- ローカルtest SPの`index.php`、`attribute-check.php`、CSS、Apache/PHP設定

### 5.2 対象外

- Shibboleth IdP標準の`/profile/*`、`/authn/*`、`/login*`
- SAML ResponseをSPへPOSTするShibboleth標準画面
- SimpleSAMLphp本体の標準画面とcookie policy
- IdP全体のHTTP公開停止またはTLS終端構成
- reverse proxy、load balancer、WAFの全体header policy
- 成果物から認証情報を除去する処理
- 外部SPの本番applicationに対するsecurity header設計
- Shibboleth IdP標準画面のCSP再設計

## 7. SH-01: 2FAS-KW servlet共通Filter

### 7.1 新規class

次のclassを追加する。

```text
io.github.yasakawa.faskw.GraphicalMatrixSecurityHeadersFilter
```

`jakarta.servlet.Filter`を実装し、次の責務だけを持つ。

- request URIから応答profileを選択する。
- profileに対応する固定headerを`chain.doFilter()`前に設定する。
- Filter無効化およびreport-only状態を監査logへ通知する。
- servlet固有の認証、認可、body生成、cache期間計算には関与しない。

Filterはrequest bodyを読み取らず、response bodyをbufferへ複製しない。header設定のためだけにresponse
wrapperを導入せず、画像・asset応答のmemory使用量とstreaming動作を変えない。

### 7.2 URLと応答profile

| URL | profile | 主な対象 |
|---|---|---|
| `/graphicalmatrix/start` | HTML | 追加認証開始 |
| `/graphicalmatrix/verify` | HTML | 追加認証検証、TOTP登録、error |
| `/graphicalmatrix/change` | HTML | 自己管理 |
| `/graphicalmatrix/graphical` | image | 認証用画像 |
| `/graphicalmatrix/assets/*` | asset | CSS、JavaScript |
| `/graphicalmatrix-admin/api/v1/*` | API | 管理API |

未知の`/graphicalmatrix/*` pathは、最低限`nosniff`、`no-referrer`、`no-store`を適用する。
実際の404生成は既存servlet containerへ委ねる。

Dispatcherは`REQUEST`と`ERROR`を対象にする。`FORWARD`、`INCLUDE`、`ASYNC`は現行利用がないため
対象外とし、将来必要になった時点でtestとともに追加する。

### 7.3 HTML profile

HTML応答へ次を設定する。

```http
Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; font-src 'self'; form-action 'self'; frame-ancestors 'none'; base-uri 'none'; object-src 'none'
X-Frame-Options: DENY
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=()
Cache-Control: no-store, no-cache, must-revalidate, max-age=0
Pragma: no-cache
Expires: 0
```

`frame-ancestors 'none'`を主制御とし、旧browser互換のため`X-Frame-Options: DENY`を併記する。
`form-action 'self'`は2FAS-KW servletだけへ適用し、SAML Responseのcross-origin POSTを妨げない。

### 7.4 API profile

管理APIへ次を設定する。

```http
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
Permissions-Policy: camera=(), microphone=(), geolocation=()
Cache-Control: no-store, no-cache, must-revalidate, max-age=0
Pragma: no-cache
Expires: 0
```

APIは成功・失敗とも`application/json;charset=UTF-8`を返す。将来のerror handlingもHTML error bodyへ
fallbackさせない。API profileではHTML実行制御としてのCSPと`X-Frame-Options`を必須としない。

### 7.5 Assetとimage profile

CSS、JavaScript、画像には次を設定する。

```http
X-Content-Type-Options: nosniff
Referrer-Policy: no-referrer
```

asset servletまたは画像servletが決定する`Cache-Control`、`Expires`、content typeをFilterが
上書きしてはならない。security header Filterはassetと画像へ`no-store`を一律適用しない。

### 7.6 Header設定方法

- 値の重複を避けるため`addHeader()`ではなく`setHeader()`を使用する。
- `Expires`は`setDateHeader("Expires", 0)`で設定する。
- HTML/APIのcache headerはFilterを正規値とし、servletの重複設定を削除する。
- asset/imageのcache headerはservletを正規値とし、Filterは変更しない。
- proxyが同名headerを追加する環境は、実応答testで重複を検出する。

### 7.7 HSTSの責務

HSTSは本Filterで設定しない。公開originのTLS終端を担当するJetty、reverse proxyまたはload balancerで
設定する。servletからHSTSを返すと、loopback HTTP、TLS offload、self-signed証明書、IP address test環境を
正しく区別できないためである。

## 8. CSP互換化

### 8.1 JavaScript外部化

`GraphicalMatrixViewRenderer.scriptBlock()`の内容を次の静的assetへ移す。

```text
assets/graphicalmatrix.js
```

配備先とbrowser URLは次のとおりである。

```text
/opt/shibboleth-idp/conf/graphicalmatrix/assets/graphicalmatrix.js
/idp/graphicalmatrix/assets/graphicalmatrix.js
```

templateはinline scriptの代わりに次を出力する。

```html
<script src="{{contextPath}}/graphicalmatrix/assets/graphicalmatrix.js" defer></script>
```

`GraphicalMatrixAssetServlet`は次の固定allowlistだけを配信し、request pathから任意filesystem pathを
組み立てない。

| pathInfo | source | content type |
|---|---|---|
| `/graphicalmatrix.css` | 設定済みCSS file | `text/css;charset=UTF-8` |
| `/graphicalmatrix.js` | 設定済みJavaScript file | `text/javascript;charset=UTF-8` |

### 8.2 JavaScript設定値

現在JavaScript文字列へ埋め込む値は、検証済み`data-*`属性へ移す。

```html
<form id="graphicalmatrix-form"
      data-choice-count="4"
      data-allow-duplicates="false"
      data-confirm-message="選択した画像で登録します。よろしいですか。">
```

- choice countは`GraphicalMatrixConfig`で検証済みの正整数だけを出力する。
- booleanは`true`または`false`だけを出力する。
- messageはOWASP EncoderでHTML attribute encodingする。
- JavaScriptは欠落、範囲外、未知値をfail closedで扱う。
- properties値をJavaScript sourceへ文字列連結しない。

### 8.3 Inline style廃止

現在templateとfallback rendererが出力する次の形式を廃止する。

```html
<div class="grid" style="--graphicalmatrix-columns: 5;">
```

通常列数とモバイル列数は`GraphicalMatrixAssetServlet`が生成CSSへ安全な整数として出力する。

```css
.grid {
  grid-template-columns: repeat(5, minmax(0, 1fr));
}

@media (max-width: 430px) {
  .grid {
    grid-template-columns: repeat(4, minmax(0, 1fr));
  }
}
```

これによりCSPの`style-src 'self'`でinline styleを許可する必要がなくなる。

### 8.4 Fallback renderer

template fileを利用できない場合のfallback HTMLもCSP対象である。次をすべて外部assetへ移す。

- `GraphicalMatrixStartServlet`のinline `<script>`
- fallback画面のinline `<style>`
- `style=`属性
- `onclick`等のinline event handler

fallbackはtemplate版と同じDOM ID、class、`data-*` contractを使い、別JavaScript実装を持たせない。
CSP互換化できないfallbackは安全のためerror画面へfail closedする。

### 8.5 Template検査

全`views/*.html`とfallback生成結果について、次が存在しないことをtestで固定する。

```text
inline <script>
<style>
style=
on*= event handler
javascript: URL
```

外部`<script src=...>`と外部`<link rel="stylesheet">`は許可する。

## 9. 設定仕様

`graphicalmatrix.properties`へ次を追加する。

```properties
# 2FAS-KW独自servletのsecurity headerを有効化する。
graphicalmatrix.securityHeaders.enabled = true

# enforceまたはreport-only。通常運用はenforceとする。
graphicalmatrix.securityHeaders.cspMode = enforce
```

### 9.1 enabled

| 値 | 動作 |
|---|---|
| `true` | profile別security headerを設定する。既定値 |
| `false` | 緊急rollbackとしてFilterを通過させるがheaderを付与しない |

`false`は恒久設定ではない。起動時または最初のrequest時にWARN auditを出し、
`graphicalmatrix-plugin-check.sh --config-only`でもwarningとする。

### 9.2 cspMode

| 値 | HTML応答 |
|---|---|
| `enforce` | `Content-Security-Policy`を返す。既定値 |
| `report-only` | `Content-Security-Policy-Report-Only`を返す |

空値および未知値は設定errorとする。任意CSP文字列をpropertiesから受け取らず、operator入力をresponse
headerへ直接反映しない。

`report-only`は独自templateの移行確認に限って使用する。report endpointは本releaseで追加せず、
browser console、Playwright console capture、で違反を確認する。

### 9.3 Config check

`GraphicalMatrixConfigCheckTool`は次を検査する。

- `enabled`がbooleanである。
- `cspMode`が`enforce`または`report-only`である。
- `enabled=false`をwarningとして表示する。
- `cspMode=report-only`をwarningとして表示する。
- JavaScript assetが通常fileであり、Jetty実行userから読める。
- 標準templateにinline script/style/event handlerが残っていない。
- Filter mappingが現在の`web.xml`に存在する。

## 10. web.xml管理

`graphicalmatrix-plugin-webxml.sh`の管理blockへ次を追加する。

```xml
<filter>
    <filter-name>GraphicalMatrixSecurityHeaders</filter-name>
    <filter-class>io.github.yasakawa.faskw.GraphicalMatrixSecurityHeadersFilter</filter-class>
</filter>
<filter-mapping>
    <filter-name>GraphicalMatrixSecurityHeaders</filter-name>
    <url-pattern>/graphicalmatrix/*</url-pattern>
    <dispatcher>REQUEST</dispatcher>
    <dispatcher>ERROR</dispatcher>
</filter-mapping>
<filter-mapping>
    <filter-name>GraphicalMatrixSecurityHeaders</filter-name>
    <url-pattern>/graphicalmatrix-admin/api/v1/*</url-pattern>
    <dispatcher>REQUEST</dispatcher>
    <dispatcher>ERROR</dispatcher>
</filter-mapping>
```

install時の要件は次のとおりである。

- markerがない場合はservletとFilterを一括追加する。
- 旧markerがある場合はmarker内部をv1.3.4形式へ更新する。
- 2回実行してもFilter定義とmappingを重複させない。
- 結果の`web.xml`をXML parserで検証してからatomic replaceする。
- 変更前fileをtimestamp付きでbackupする。
- `--apply`なしでは変更予定だけを表示する。
- `build.sh`とJetty再起動は自動実行せず、次のcommandを表示する。

remove時は2FAS-KW marker内のFilter、mapping、servletだけを削除する。他pluginのFilterを削除してはならない。
marker外に旧手動mappingがある場合は自動で広範囲を書き換えず、manual entriesとFilter欠落を表示する。

## 11. SH-02: ローカルtest SPのheader強化

### 11.1 境界

ローカルtest SPのhardeningは次のapplicationだけへ適用する。

```text
/var/www/2faskw-localsp/index.php
/var/www/2faskw-localsp/attribute-check.php
/var/www/2faskw-localsp/2faskw-localsp.css
```

`/simplesaml` AliasはSimpleSAMLphp自身のCSP、SAML binding、session、error pageを使うため、test
application用CSPのscope外とする。

### 11.2 Apache設定

installerが生成するDocumentRoot用`<Directory>`へ次を追加する。

```apache
<Directory "/var/www/2faskw-localsp">
    Require all granted
    AllowOverride None
    Options -Indexes
    DirectoryIndex index.php

    Header always set Content-Security-Policy "default-src 'none'; style-src 'self'; img-src 'self' data:; form-action 'self'; frame-ancestors 'none'; base-uri 'none'; object-src 'none'"
    Header always set X-Frame-Options "DENY"
    Header always set X-Content-Type-Options "nosniff"
    Header always set Referrer-Policy "no-referrer"
    Header always set Permissions-Policy "camera=(), microphone=(), geolocation=()"
    Header always set Cache-Control "no-store, no-cache, must-revalidate"
    Header always set Pragma "no-cache"
    Header always set Expires "0"
    Header always unset X-Powered-By
</Directory>
```

適用前に`headers_module`を確認し、利用できない場合は明確なerrorで停止する。

```bash
sudo httpd -M | grep -F headers_module
```

PHP applicationはJavaScriptを使用しないため`script-src`を許可しない。将来追加する場合は同一originの
外部fileへ分離し、`script-src 'self'`を明示する。

### 11.3 CSSとversion情報

`index.php`と`attribute-check.php`のinline styleは次へ移す。

```text
/var/www/2faskw-localsp/2faskw-localsp.css
```

PHPは外部stylesheetだけを参照する。利用者ID、属性ID、属性値は現在と同様に`htmlspecialchars()`で
escapeする。

`X-Powered-By`はApache scopeで必ずunsetする。test専用serverではPHP設定へ
`expose_php = Off`も適用する。system-wideの`/etc/php.d`を変更する場合は他applicationへの影響を
planへ表示し、既存共有環境ではoperatorの明示承認なしに変更しない。

test専用hostでは`ServerTokens Prod`と`ServerSignature Off`を使う。これらはserver-wide directiveで
あるため、共有Apacheでは`--allow-existing`だけを理由に暗黙変更しない。

### 11.4 HSTS

HSTSは次の3状態とする。

```text
auto   trusted certificateかつDNS hostnameの場合だけ有効
true   operatorが影響を確認して明示的に有効化
false  HSTSを送信しない
```

既定値は`auto`とする。IP addressまたはself-signed証明書を使うローカルtestではHSTSを返さない。
有効時はHTTPS VirtualHostで`Strict-Transport-Security: max-age=31536000`を返す。

`includeSubDomains`は配下domainすべてがHTTPSであることをoperatorが保証した場合だけ使用し、test
installerは`preload`を設定しない。

## 12. Installer処理

`local-unattended-install.sh`と`local-unattended-SP-install.sh`は共通要件で次を行う。

1. `mod_headers`、PHP-FPM、TLS条件をpreflightする。
2. Apache、PHP、CSS、PHP画面の変更予定とHSTS判定を表示する。
3. 既存fileを同一timestampでbackupする。
4. 一時fileへApache/PHP/CSS設定を生成する。
5. `php -l`、`httpd -t`、必要module検査を行う。
6. 検査成功後だけatomic installする。
7. PHP-FPMとApacheをreloadまたはrestartする。
8. applicationと`/simplesaml`の実応答headerを別々に検証する。
9. 検証結果、backup path、rollback commandを最後に表示する。

再実行時はdirectiveを重複生成しない。`--allow-existing`では既存custom設定を全面上書きせず、
installer管理blockだけを更新する。

## 13. 導入・更新手順

### 13.1 IdP plugin

配布物を既存手順で上書きinstallした後、Filterとassetを配備する。

```bash
# 設定およびweb.xml変更予定を確認する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-plugin-config.sh \
  --idp-home /opt/shibboleth-idp

# 確認した変更を適用する。
sudo /opt/shibboleth-idp/bin/graphicalmatrix-plugin-config.sh \
  --idp-home /opt/shibboleth-idp \
  --apply

# IdP web applicationを再構築する。
sudo /opt/shibboleth-idp/bin/build.sh

# 新しいFilter mappingとassetを読み込むためJettyを再起動する。
sudo systemctl restart jetty-idp.service
```

listenerが準備完了するまで待ってから確認する。

```bash
until curl --noproxy '*' -fsSI --connect-timeout 2 --max-time 5 \
  http://127.0.0.1:8080/idp/status >/dev/null 2>&1; do
  echo 'Waiting for Jetty...'
  sleep 2
done

sudo /opt/shibboleth-idp/bin/graphicalmatrix-plugin-check.sh \
  --idp-home /opt/shibboleth-idp \
  --config-only
```

### 13.2 独自template

独自templateはenforce前にinline codeを除去する。一時確認では次を使用できる。

```properties
graphicalmatrix.securityHeaders.enabled = true
graphicalmatrix.securityHeaders.cspMode = report-only
```

Playwrightのbrowser consoleで違反がないことを確認後、`enforce`へ変更する。report-onlyを恒久運用しない。

## 14. Test設計

### 14.1 Unit test

新規または拡張testで次を固定する。

- HTML profileへ必須headerが各1値だけ設定される。
- HTMLの200、302、400、403、404、500相当経路でheaderが残る。
- APIの成功・4xx・5xxへ`nosniff`と`no-store`が付く。
- assetの既存cache headerをFilterが上書きしない。
- imageの認可およびcontent typeをFilterが変更しない。
- `/profile/SAML2/POST/SSO`等にFilter mappingがない。
- CSPに`unsafe-inline`、`unsafe-eval`、wildcard sourceがない。
- report-only時にenforce headerが同時出力されない。
- disabled時にwarning状態を検出できる。
- JavaScript asset以外のpathが404になる。
- JavaScript設定値の欠落、範囲外、未知booleanでsubmit可能にならない。
- 生成HTMLにinline script/style/event handlerがない。

## 16. Compatibility

### 16.1 標準template

標準templateは同じreleaseで外部asset化するため、既定設定でenforceを有効にできる。画面の操作と表示は
v1.3.3を維持する。

### 16.2 独自template

inline script/styleに依存する独自templateは、enforce適用後に動かなくなる。更新前検査で対象fileと該当行を
表示する。暗黙に`unsafe-inline`を許可して互換性を保たない。

### 16.3 Reverse proxy

proxyが同名headerを設定している場合は値が重複し得る。Filterとproxyのどちらを正規設定源とするか決め、
実応答で1値に統一する。HSTSはTLS終端側を正規設定源とする。

## 17. Rollback

CSP障害時は最初に次へ変更して違反箇所を特定する。

```properties
graphicalmatrix.securityHeaders.enabled = true
graphicalmatrix.securityHeaders.cspMode = report-only
```

Filter全体の無効化は`nosniff`、clickjacking対策、no-storeも失うため最終手段とする。

```properties
graphicalmatrix.securityHeaders.enabled = false
```

外部化したJavaScript/CSSはrollback時もinlineへ戻さない。

`web.xml`は管理scriptが作成したbackupから復元し、`build.sh`、Jetty再起動、status確認を行う。
他pluginのmappingを含む`web.xml`全体を、世代確認なしに古いbackupへ戻してはならない。

ローカルtest SPではApache、PHP、CSS、`index.php`、`attribute-check.php`を同一timestampのbackupから
まとめて復元する。復元後に`php -l`と`httpd -t`を通してからserviceをreloadする。

HSTSを一度browserへ配信した場合、server fileを戻してもbrowser側状態は直ちに消えない。HSTS有効化前に
hostname、証明書、有効期間を確認する。

## 18. 監査と運用可視性

| 状態 | severity | 表示 |
|---|---|---|
| security headers enabled + enforce | OK | 正常 |
| security headers enabled + report-only | WARN | 移行確認中 |
| security headers disabled | WARN | 緊急rollback状態 |
| JavaScript asset欠落・読取不能 | FAIL | 配備中止 |

## 21. Release note要約

v1.3.4では、2FAS-KW独自servletに共通security header Filterを追加し、CSP、clickjacking対策、
`nosniff`、referrer制御、browser capability制限、no-storeを応答種別ごとに統一する。厳格なCSPと
互換にするため、認証画面のinline JavaScript/styleを同一originの管理assetへ移す。

ローカルtest SPではapplicationのDocumentRootだけへheaderを適用し、SimpleSAMLphp標準画面とSAML POSTを
妨げない。あわせてPHP/Apache version露出、inline style、cache保存を抑止する。

HSTSは2FAS-KW servletでは設定せず、TLS終端側の責務とする。IP addressやself-signed証明書を使う
local testでは既定で送信しない。
