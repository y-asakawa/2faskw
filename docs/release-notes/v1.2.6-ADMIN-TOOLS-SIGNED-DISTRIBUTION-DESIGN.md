# v1.2.6 Admin Tools署名付き別配布 詳細設計

> 実装状態: ビルド、署名、検証、公開手順を実装済み。`version.ini`のv1.2.6更新と
> 実リリース鍵による署名は、v1.2.6のリリース準備時に行う。

## 1. 目的

2FAS-KW Admin ToolsをIdPプラグイン本体から分離した任意導入コンポーネントとして、
固定名ZIPとdetached GPG signatureで公開する。

v1.2.6では、現在生成しているバージョン付きAdmin Tools ZIPを維持したうえで、
GitHub Releaseへ次の固定名ファイルを追加する。

```text
2faskw-admin-tools.zip
2faskw-admin-tools.zip.asc
```

Admin Toolsは、CSVプロビジョニング、DB管理CLI、sequence migration、
WebAuthn credential管理を必要とする管理者だけが導入する。
Shibboleth IdPの`plugin.sh`によるインストール対象にはせず、IdPプラグイン本体にも
同梱しない。

## 2. 実装前の状態

`scripts/build-plugin-package.sh`は、次のバージョン付きZIPを生成している。

```text
target/admin-dist/2faskw-admin-tools-<VERSION>.zip
```

実装前には次の不足があった。

- 固定名`2faskw-admin-tools.zip`を生成していない。
- Admin Tools ZIPのdetached signatureを生成していない。
- 公開用`SHA256SUMS`にAdmin Tools ZIPを含めていない。
- GitHub Releaseの固定名公開ファイルにAdmin Toolsを含めていない。
- クリーンな鍵リングを使ったAdmin Tools固有の署名検証手順がない。
- IdPプラグイン本体とAdmin Toolsの導入経路の違いが、公開手順上で明確になっていない。

## 3. 設計方針

- `version.ini`をAdmin Toolsのバージョン情報の正とする。
- 通常ビルドは秘密鍵を必要とせず、署名なし成果物を生成できる状態を維持する。
- 署名は、秘密鍵を保管するリリース環境で明示的に実行した場合だけ行う。
- 署名対象はビルド完了後の固定名ファイルとし、署名後にアーカイブを変更しない。
- 公開鍵とfingerprintはIdPプラグイン本体と同じものを使用する。
- 秘密鍵、passphrase、失効証明書、秘密鍵バックアップは配布物とGitへ含めない。
- Admin ToolsをShibboleth plugin metadataの自動検出対象にしない。
- 固定名ZIPとバージョン付きZIPは同一バイト列とし、展開後のトップレベル名には
  バージョンを残す。
- 配布物へ実環境の設定、credential、証明書、秘密鍵、CSV、ログを含めない。

## 4. 対象範囲

### 4.1 対象

- 固定名Admin Tools ZIPの生成
- Admin Tools ZIPの署名
- `SHA256SUMS`と`SHA256SUMS.asc`への組込み
- GitHub Releaseへの公開
- 公開後のダウンロード、署名、checksum、展開内容の検証
- Admin Toolsの手動インストールとアップグレード確認
- パッケージ内容に対する秘密情報・ローカルファイル混入検査

### 4.2 対象外

- `plugin.sh`によるAdmin Toolsのインストール
- Shibboleth plugin metadataによるAdmin Toolsの自動検出
- Admin Toolsの自動アップデート
- 実環境の`admin.properties`、DB password、TLS client keyの配布
- CSVファイルのGitHub Releaseへの添付
- リリース署名鍵の生成、バックアップ、失効手続きそのもの
- コンテナイメージ、RPM、DEBによる配布

## 5. 成果物

### 5.1 ビルド成果物

ビルド後に次を生成する。

```text
target/admin-dist/
  2faskw-admin-tools-<VERSION>/
  2faskw-admin-tools-<VERSION>.zip
  2faskw-admin-tools.zip
```

署名実行後は次を追加する。

```text
target/admin-dist/
  2faskw-admin-tools-<VERSION>.zip.asc
  2faskw-admin-tools.zip.asc
```

バージョン付きZIPとその署名は、監査、直接配布、過去バージョン保管用とする。
GitHub Releaseで必須とするのは固定名ZIPと固定名ZIPの署名である。

### 5.2 GitHub Release公開ファイル

固定名の必須公開ファイルは次の8ファイルとする。

```text
2faskw-idp-plugin.tar.gz
2faskw-idp-plugin.tar.gz.asc
2faskw-idp-plugin.zip
2faskw-idp-plugin.zip.asc
2faskw-admin-tools.zip
2faskw-admin-tools.zip.asc
SHA256SUMS
SHA256SUMS.asc
```

バージョン付きアーカイブを追加公開する場合は、対応する`.asc`も同時に公開する。
署名のないバージョン付きアーカイブだけを公開してはならない。

## 6. アーカイブ生成

### 6.1 ファイル名とトップレベルディレクトリ

固定名ZIPの外側のファイル名にはバージョンを含めない。
ZIP内のトップレベルディレクトリにはバージョンを含める。

```text
2faskw-admin-tools.zip
└── 2faskw-admin-tools-1.2.6/
```

固定名ZIPとバージョン付きZIPを別々に圧縮すると、ファイル順序やZIP metadataの差で
異なるバイト列になる可能性がある。このため、バージョン付きZIPを一度だけ生成し、
固定名ZIPはそのファイルをコピーして作成する。

```text
2faskw-admin-tools-1.2.6.zip
    -- byte-for-byte copy -->
2faskw-admin-tools.zip
```

以下が一致することをビルド時に検査する。

```text
SHA-256(2faskw-admin-tools-1.2.6.zip)
  = SHA-256(2faskw-admin-tools.zip)
```

### 6.2 パッケージ内容

Admin Tools ZIPには少なくとも次を含める。

```text
2faskw-admin-tools-<VERSION>/
  README.md
  LICENSE
  NOTICE
  THIRD-PARTY-NOTICES.md
  bin/
    graphicalmatrix-db.sh
    graphicalmatrix-db-migration.sh
    graphicalmatrix-admin-install.sh
    graphicalmatrix-csv-import-runner.sh
  lib/
    2faskw-idp-plugin-<VERSION>.jar
    required-runtime-libraries.jar
  conf/graphicalmatrix/
    db.properties.adminnew
    ldap.properties.adminnew
    graphicalmatrix.properties.adminnew
    admin.properties.adminnew
    postgresql-schema.sql
  examples/systemd/
  package-metadata/
    PACKAGE-CONTENTS.txt
    PACKAGE-MANIFEST.sha256
```

実際の依存JAR名はビルド時の依存解決結果に従う。
`PACKAGE-CONTENTS.txt`と`PACKAGE-MANIFEST.sha256`は、パッケージ内部の検査に使用する。
詳細な`docs/`はZIPへ含めない。配布専用`README.md`には最小限のdry-runと導入コマンド、
GitHub上の`ADMIN-TOOLS.md`、`CONFIG-REFERENCE.md`、`UPGRADE.md`、`SECURITY.md`へのURLを
記載する。

### 6.3 禁止ファイル

次をZIPへ含めてはならない。

```text
.DS_Store
._*
Thumbs.db
*.swp
*.tmp
*.bak
*.log
*.csv
target/
.git/
.github/
credentials/
private key
secret key
password
API token
実環境の*.properties
```

ファイル名だけでなく内容も検査し、次のような実値を検出した場合はビルドを失敗させる。

- 平文の`graphicalmatrix.db.password`
- 平文の`graphicalmatrix.sequence.keyword`
- 平文の`graphicalmatrix.sequence.aesKey`
- 平文の`graphicalmatrix.sequence.pepper`
- 平文のLDAP bind credential
- `BEGIN ... PRIVATE KEY`
- `BEGIN PGP PRIVATE KEY BLOCK`
- 実環境用のclient certificateと秘密鍵

サンプルに含めるpassword fileやcertificateのパスは例示値だけとし、ファイル本体は含めない。

## 7. 署名処理

### 7.1 実行条件

署名は通常ビルドの既定動作にしない。v1.2.6では、リリース担当者だけが実行する
明示的な署名モードを追加する。

```bash
./scripts/build-plugin-package.sh --sign
```

`--sign`を指定しない場合は、`.asc`と`SHA256SUMS.asc`を生成しない。
`--sign`指定時は、次をすべて満たさなければ失敗する。

- `release/keys/RELEASE-KEY-FINGERPRINT.txt`が40桁のfingerprintを1件だけ含む。
- fingerprintに一致する秘密鍵がローカルGnuPG keyringに存在する。
- `bootstrap/keys.txt`の公開鍵fingerprintが同じ値である。
- ビルド対象のGit worktreeに未コミットの追跡対象変更がない。
- 固定名アーカイブが存在し、空ファイルではない。
- 既存の古い署名ファイルを削除した後に新しい署名を生成できる。

passphraseをコマンドライン引数、環境変数、設定ファイルへ渡さない。
GnuPG agentまたはpinentryを使用する。

### 7.2 detached signature

固定名Admin Tools ZIPにはASCII armored detached signatureを生成する。

```bash
gpg \
  --local-user "$RELEASE_FINGERPRINT" \
  --armor \
  --detach-sign \
  --output target/admin-dist/2faskw-admin-tools.zip.asc \
  target/admin-dist/2faskw-admin-tools.zip
```

バージョン付きZIPにも同じ方法で署名する。
署名生成後は、署名対象のサイズとSHA-256を監査用出力へ表示する。

## 8. SHA256SUMS

`target/plugin-dist/SHA256SUMS`には、固定名アーカイブ3件だけをbasenameで記録する。

```text
<sha256>  2faskw-idp-plugin.zip
<sha256>  2faskw-idp-plugin.tar.gz
<sha256>  2faskw-admin-tools.zip
```

`.asc`ファイルと`SHA256SUMS.asc`自身は`SHA256SUMS`へ含めない。
チェックサム生成は、3件すべての固定名アーカイブ生成後に行う。

`SHA256SUMS`を生成した後、そのファイルへdetached signatureを作成する。

```text
SHA256SUMS
SHA256SUMS.asc
```

Releaseへアップロードする直前に、公開用一時ディレクトリへ8ファイルを集め、
そのディレクトリでchecksum検証を行う。これにより、異なるディレクトリにある
Admin Tools ZIPもbasenameで検証できる。

## 9. 署名検証

### 9.1 独立した一時鍵リング

通常利用中のGnuPG keyringの信頼設定に依存しないよう、空の一時鍵リングで検証する。

検証対象は次の4署名とする。

```text
2faskw-idp-plugin.zip.asc
2faskw-idp-plugin.tar.gz.asc
2faskw-admin-tools.zip.asc
SHA256SUMS.asc
```

検証では、単に終了コードと`Good signature`の文字列だけを見ない。
`--status-fd`の`VALIDSIG`に含まれるfingerprintが
`RELEASE-KEY-FINGERPRINT.txt`と完全一致することを必須とする。

一時鍵リングで表示される「鍵の所有者を信頼できない」という警告は、
暗号学的署名の失敗ではない。fingerprintは、リポジトリとは独立した公開経路でも確認する。

### 9.2 ZIP内部検査

署名とchecksumが正しい場合でも、次を検査する。

- ZIP entryに絶対パスがない。
- `../`による展開先外への書込みがない。
- symlinkを含まない。
- 同じパスの重複entryがない。
- entry数と展開後サイズが上限以内である。
- `PACKAGE-MANIFEST.sha256`が一致する。
- トップレベルディレクトリが1件だけで、期待したバージョン名である。

## 10. 公開

### 10.1 公開順序

1. `version.ini`、公開鍵、fingerprint、ビルドスクリプト、公開文書をmainへ反映する。
2. mainを最新化し、main上のソースから再ビルドする。
3. リリース環境で署名する。
4. 独立鍵リングで署名とfingerprintを検証する。
5. checksumとZIP内部を検証する。
6. mainの対象コミットへReleaseタグを作成する。
7. GitHub Releaseへ固定名8ファイルをアップロードする。
8. GitHub上のファイルを再ダウンロードし、ローカル生成物と同じ検査を行う。

### 10.2 公開先

固定名Admin Tools ZIPは次の形式で公開する。

```text
https://github.com/y-asakawa/2faskw/releases/download/v<VERSION>/2faskw-admin-tools.zip
https://github.com/y-asakawa/2faskw/releases/download/v<VERSION>/2faskw-admin-tools.zip.asc
```

Shibboleth plugin metadataの`downloadURL`と`baseName`は、IdPプラグイン本体専用のままとする。

## 11. インストール

Admin Toolsは次の順に導入する。

1. ZIP、`.asc`、公開鍵、公開fingerprintを取得する。
2. 一時鍵リングで署名とfingerprintを検証する。
3. `SHA256SUMS`を検証する。
4. 一時ディレクトリへ展開する。
5. installerをdry-runで実行する。
6. 内容を確認後、`--apply`で導入する。
7. DB credential、TLS client certificate、`admin.properties`を別途設定する。
8. 読取り専用CLIで接続確認する。
9. CSV自動処理は、必要な環境だけで明示的に有効化する。

署名検証前にZIPをroot権限で展開・実行してはならない。

## 12. アップグレードとロールバック

### 12.1 アップグレード

- 新しいZIPを別ディレクトリへ展開する。
- 既存`/opt/graphicalmatrix-admin`をinstallerが世代バックアップする。
- `*.adminnew`は既存設定を上書きせず、差分確認用として保存する。
- DB credential、Admin Tools専用証明書、`admin.properties`は保持する。
- JARとスクリプトのバージョンが同一であることを確認する。

### 12.2 ロールバック

導入後に問題が発生した場合は、installerが作成した次のバックアップへ戻す。

```text
/opt/graphicalmatrix-admin.bak.YYYYMMDDHHMMSS
```

ロールバック時にDB schemaや登録データを自動的に戻さない。
Admin ToolsのファイルロールバックとDBデータの復旧は分離する。

## 13. 異常時動作

| 異常 | 動作 |
| --- | --- |
| 秘密鍵が存在しない | `--sign`を失敗させ、未署名ファイルを公式成果物として扱わない |
| 公開鍵と秘密鍵のfingerprint不一致 | 署名を開始しない |
| Admin Tools ZIPが存在しない | checksumと署名を生成しない |
| 古い`.asc`が残っている | 署名前に削除し、生成失敗時は署名なしとして扱う |
| checksum不一致 | Releaseへアップロードしない |
| `VALIDSIG` fingerprint不一致 | 署名検証失敗とする |
| ZIPに禁止ファイルがある | ビルドまたは公開前検査を失敗させる |
| GitHub Releaseの一部だけアップロード失敗 | Releaseを公開完了扱いにせず、8件を再確認する |

## 15. テスト

### 15.1 ビルド試験

- 秘密鍵がない環境で通常ビルドが成功する。
- 固定名とバージョン付きAdmin Tools ZIPのSHA-256が一致する。
- バージョン付きトップレベルディレクトリが維持される。
- `version.ini`とJAR、README、ディレクトリ名のバージョンが一致する。

### 15.2 署名試験

- 正しい秘密鍵で4つの必須署名を生成できる。
- 別の秘密鍵を指定した場合はfingerprint不一致で失敗する。
- 公開鍵だけの一時鍵リングで4署名を検証できる。
- 改変したZIP、`.asc`、`SHA256SUMS`が検証で拒否される。

### 15.3 パッケージ試験

- ZIPに必要ファイルだけが含まれる。
- ZIPに詳細な`docs/`が含まれず、READMEに公式文書URLが含まれる。
- 秘密情報、ローカルファイル、Git metadataが含まれない。
- symlink、絶対パス、path traversal entryがない。
- `PACKAGE-MANIFEST.sha256`が一致する。

### 15.4 導入試験

- 未導入環境でdry-runと`--apply`が成功する。
- 既存環境で設定を保持したままアップグレードできる。
- 読取り専用CLIがDBへ接続できる。
- IdPの`web.xml`、Jetty、IdPプラグインファイルを変更しない。
- `plugin.sh -l`のIdPプラグイン一覧へAdmin Toolsが別プラグインとして現れない。

## 16. 受入条件

- GitHub Releaseに固定名8ファイルが存在する。
- `2faskw-admin-tools.zip`と`.asc`を公開鍵だけで検証できる。
- `VALIDSIG` fingerprintが公開fingerprintと完全一致する。
- `SHA256SUMS`がIdPプラグイン2件とAdmin Tools ZIPを検証できる。
- Admin Tools ZIPに秘密情報とローカル由来ファイルがない。
- Admin ToolsをIdPプラグイン本体とは独立して導入できる。
- 通常ビルドでは秘密鍵を要求せず、明示的な署名操作でだけ署名が発生する。
- Admin Toolsの公開によってShibboleth plugin metadataの既存動作が変わらない。
