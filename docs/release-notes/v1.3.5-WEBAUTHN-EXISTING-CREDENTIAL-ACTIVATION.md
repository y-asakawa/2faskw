# v1.3.5 WebAuthn Existing Credential Activation

## 1. Purpose

This change makes the MFA method selection match the user's explicit choice when a usable WebAuthn credential
already exists. A user who has reauthenticated through 2FAS-KW self-service and selects WebAuthn no longer has to
register a duplicate credential or press `Finish` in the Shibboleth WebAuthn registration profile.

## 2. Previous behavior

The previous integration changed `mfa_method` only from the WebAuthn Plugin's successful `AddKey` audit hook.
Selecting WebAuthn always opened the registration profile. If the user already had a credential and pressed
`Finish` without adding another key, the profile ended with `Your session has ended`, no success hook ran, and the
method remained GraphicalMatrix.

## 3. New behavior

After the self-service authentication and enrollment state checks succeed, 2FAS-KW queries the active Shibboleth
WebAuthn `CredentialRepository` through `getRegistrationsByUsername`.

| Credential lookup | Result |
| --- | --- |
| One or more credentials | Change the method to WebAuthn with an enrollment `state_version` compare-and-set and show the completion page. |
| No credentials | Keep the current method and start the official registration profile. The method changes only after the `AddKey` success hook. |
| Repository unavailable | Keep the current method and use the existing registration path. No unverified method change is performed. |

The lookup uses the configured WebAuthn repository abstraction. It does not depend on a specific JDBC table or
LDAP layout, and the WebAuthn Plugin remains an optional runtime component.

## 4. Concurrency and failure handling

The direct change calls `updateMfaMethodIfCurrent` with the state version captured by the authenticated self-service
transaction. An administrator action or another concurrent method change causes a conflict and requires the user to
start again. Repository lookup failures never cause a direct switch.

## 5. Audit events

An existing-credential activation records:

```text
event=WEBAUTHN_REGISTER_ACTIVATE result=OK detail=existing_credential,mfa_method=WebAuthn
```

A new registration continues to record `WEBAUTHN_REGISTER_START`, followed by
`WEBAUTHN_REGISTER_ACTIVATE` only after the credential has been saved.

Credential IDs, public keys, and authenticator secrets are not written to the 2FAS-KW audit log.

## 6. Compatibility

No operator command, database schema, or WebAuthn credential format changes. Shibboleth WebAuthn Plugin 1.3.0 or
later remains required for self-service WebAuthn integration. Deployments must rebuild the IdP WAR and restart Jetty
after updating the Plugin JAR.

The distribution also includes `views/webauthn/webauthn-authn.vm.idpnew`. This override identifies the WebAuthn
credential-registration requester, explains that the current credential is required for identity verification, and
hides the registration link on that reauthentication screen. The normal authentication screen links to the
query-free standalone registration profile instead of `?reg=inline`. Existing IdP templates are not overwritten;
the installer leaves the new template as an `.idpnew.TIMESTAMP` file for review and integration.

## 7. Verification

1. Confirm that `graphicalmatrix-db.sh webauthn-list USER` shows an existing credential.
2. Set the test user's current method to GraphicalMatrix and authenticate to the self-service profile.
3. Select WebAuthn.
4. Confirm that the completion page appears without opening the registration profile.
5. Confirm that `graphicalmatrix-db.sh show USER` reports `mfa_method=WebAuthn`.
6. Confirm the `existing_credential` activation event in `graphicalmatrix-audit.log`.

For a user with no credential, verify that registration is still required and that cancelling or pressing `Finish`
without adding a key leaves the original MFA method unchanged.
