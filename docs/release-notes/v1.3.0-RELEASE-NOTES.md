# 2FAS-KW v1.3.0 統合リリースノート

## 1. 目的

v1.3.0は、v1.2.7で導入したStandalone DashboardとSP管理CLIを継承し、SP別LDAP属性
アクセス制御および属性カタログCLIを追加する統合リリースである。

v1.2.7の公開済み配布物、Git tag、履歴ドキュメントは変更しない。v1.3.0の配布物では、
Dashboard、IdPプラグイン、Admin Toolsをそれぞれ同じ`1.3.0`のバージョンで生成する。

## 2. v1.3.0に含まれる機能

| 機能 | 内容 | 初期状態 |
| --- | --- | --- |
| Standalone Dashboard | `graphicalmatrix-audit.log`を参照専用で可視化する別配布Dashboard。 | 未導入。必要な環境だけ別途導入する。 |
| SP管理CLI | `graphicalmatrix-sp.sh`によるSP metadata、属性release、SP別MFA方針のローカル管理。 | 無効。明示的な初期化まで既存設定を変更しない。 |
| 属性カタログCLI | 解決可能な属性の検出、利用目的の承認、SP向けattribute profile管理。 | catalog未初期化。既存の属性releaseは保持する。 |
| SP別LDAP属性アクセス制御 | IdP内部の未filter属性を使い、SPごとのアクセス可否を判定する。 | 無効。`access init --apply`まで既存認証を変更しない。 |

SP管理CLIはHTTP API、管理Web UI、外部公開listenerを追加しない。Dashboardも認証処理と別プロセスで
動作し、IdP、LDAP、MFA保存DBへ接続しない。

## 3. v1.2.7から更新する場合

v1.2.7で導入済みのDashboardまたはSP管理CLIは、v1.3.0への更新だけで設定が自動変更されない。

- Dashboardを使う場合は、`2faskw-dashboard-1.3.0.zip`へ更新する。
- SP管理CLIを初期化済みの場合は、`init`を再実行しない。
- SP別LDAP属性アクセス制御を使う環境だけ、`access init`のdry-runを確認してから
  `access init --apply`、IdP build、Jetty再起動を実施する。
- 属性カタログを使う環境だけ、`attributes discover`で解決状態とSAML mappingを確認してから
  属性を承認し、managed profileを作成する。

アクセス制御を初期化しない限り、v1.2.7以前のSP認証、属性release、MFA方針は変更しない。
