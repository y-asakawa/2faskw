# v1.3.1 LDAP Resolver属性追加CLI

## 1. 目的

LDAPに存在する属性をSP別アクセス制御へ利用するには、Shibboleth IdPのAttribute Resolverがその属性を
解決できなければならない。v1.3.1では、`attribute-resolver.xml`を手作業で編集する代わりに、
`graphicalmatrix-sp.sh attributes resolver init`でLDAP DataConnectorを初期化し、
`attributes resolver add`でLDAP属性の`AttributeDefinition`を追加できる。

この機能は属性解決の設定だけを管理する。属性カタログでの用途承認、SPへの属性release、SP別アクセス
policyは自動変更しない。

## 2. コマンド

```bash
# LDAP DataConnector初期化のdry-run
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh \
  attributes resolver init

# LDAP DataConnectorが存在しない場合のapply
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh \
  attributes resolver init \
  --data-connector graphicalmatrixLdap \
  --apply --confirm graphicalmatrixLdap

# 属性追加のdry-run
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh \
  attributes resolver add businessCategory

# 属性追加のapply
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh \
  attributes resolver add businessCategory \
  --data-connector graphicalmatrixLdap \
  --apply --confirm businessCategory
```

IdP属性IDとLDAP属性名が異なる場合は、`--source-attribute`を指定する。

```bash
sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh \
  attributes resolver add organizationCategory \
  --source-attribute businessCategory \
  --data-connector graphicalmatrixLdap \
  --apply --confirm organizationCategory
```

## 3. DataConnector選択

`resolver init`は既存のLDAP DataConnectorを上書きしない。LDAP DataConnectorが存在しない場合だけ、
`conf/ldap.properties`と`credentials/secrets.properties`の`idp.attribute.resolver.LDAP.*`設定を
参照する`graphicalmatrixLdap`を追加する。既定の検索属性は`uid`であり、異なる場合は
`--search-attribute LDAP_ATTRIBUTE`を指定する。

`attribute-resolver.xml`内の`xsi:type="LDAPDirectory"`であるDataConnectorを対象とする。候補が1つの場合は
自動選択する。複数ある場合は誤ったLDAPへの接続を避けるため自動選択せず、候補IDを表示して停止する。
管理者は`--data-connector ID`で対象を明示する。

対象DataConnectorに`ReturnAttributes`が存在し、追加するLDAP属性が含まれていない場合は、その一覧にも
属性を追加する。`ReturnAttributes`自体がないDataConnectorには新設しない。

## 4. 安全性と復旧

- dry-runを既定とし、変更には`--apply --confirm ATTRIBUTE`を必要とする。
- applyには`sp-management.properties`の`graphicalmatrix.sp.management.enabled = true`を必要とする。
- 属性ID、LDAP属性名、DataConnector IDは安全な識別子形式に制限する。
- credential、password、tokenなど2FAS-KWでblock対象となる属性は、IdP属性IDとLDAP source属性の
  どちらに指定されても追加を拒否する。
- 既存の同名`AttributeDefinition`は上書きせず、競合として停止する。
- XMLのDTD、外部entity、XIncludeを無効化し、symlinkと2 MiBを超えるファイルを拒否する。
- 変更前の`attribute-resolver.xml`を既存のSP管理backup領域へ保存する。
- 書込みは一時ファイルからのatomic replaceを使用し、既存の所有者、group、modeを維持する。
- 適用処理が失敗した場合は変更前のファイルを復元する。
- 操作結果を`graphicalmatrix-sp-management-audit.log`へ記録する。

## 5. 反映と確認

Attribute Resolverの変更は実行中IdPへ即時反映しない。CLIが表示する次の手順に従ってWARを再構築し、
Jettyを再起動する。

```bash
sudo /opt/shibboleth-idp/bin/build.sh
sudo systemctl restart jetty-idp.service

sudo /opt/shibboleth-idp/bin/graphicalmatrix-sp.sh attributes discover \
  --sp SP_NAME --user USER
```

対象属性が`runtime-observed`にならない場合は、LDAP上の属性値、Attribute Resolverが使用するbindユーザーの
read権限、DataConnectorのbase DNと検索filterを確認する。`resolver add`だけではLDAP ACL/ACIを変更しない。
