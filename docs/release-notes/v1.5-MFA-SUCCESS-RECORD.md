# 共通MFA成功日時・監査集約 実装ノート

状態: ローカル実装・自動回帰試験済み。設計対象はv1.5系列、正式リリース番号は未確定。
v1.4.1候補作業ツリーのN1〜N4／RESET確認を基準に追加し、本作業ではバージョン、ブランチ、
公開タグを変更しない。公開済みバイナリへの追加設定だけでは本機能は有効にならない。

## 変更内容

- GraphicalMatrix／TOTP／WebAuthnの共通完了検査で最新成功日時を記録する。
- 画像の単独照合とTOTP登録から日時代入だけを外す。カウンター・登録状態・世代進行は維持する。
- 日時保存と成功監査の独立ON/OFFを追加する。いずれも既定ON。
- 共通イベント`MFA_COMPLETE/OK`を既存の監査ファイルへ追加する。
- Dashboardの認証カテゴリへ追加し、方式・scope・保存結果の内訳を表示する。
- 公式TOTPが返す`TOTPPrincipal`を完了検査で読み取れるよう修正。TOTP検証成功後の誤拒否と、それに伴う成功日時の未記録を防ぐ。利用者・flow・世代の一致検査は維持する。
- 公式WebAuthn 1.4.2の第二要素結果でUsernamePrincipalが欠落する場合、同一Subjectへ束縛された成功時の正規化名だけを許可する。過去結果・無関係なSubjectや名前の矛盾は拒否し、公式プラグインは改変しない。

## 設定と互換性

```properties
graphicalmatrix.mfa.successRecord.enabled = true
graphicalmatrix.mfa.successRecord.queryTimeoutSeconds = 1
graphicalmatrix.mfa.completionAudit.enabled = true
```

timeoutは1～5秒で付加SQL UPDATEだけが対象。OFFでも登録状態の必須SELECT、照合・登録に必要な
既存UPDATEは残る。設定の不正値はconfig検査で拒否する。CLIの引数・列名、APIの`lastSuccessAt`、
DB credential形式、TOTP window、WebAuthn鍵、MFA方針は変更しない。

`last_success`は最終MFA完了検査日時であり、SPへのアクセス許可日時・設定変更履歴・今回の新しい
factor操作の証拠ではない。自己管理再認証も含む。旧値は変換せず、OFF期間を自動補完しない。

## 保存・障害・認可

必須状態lookupの接続を共用し、通常最大1回の条件付きUPDATE／LDAP modifyを試みる。
日時は巻き戻さず、登録世代は進めない。未来の保存値を自動で修正しない。
LDAPはraw値の一致・属性不在を含むcritical assertionを使用し、非対応時に無条件更新へ逃げない。
0件更新／assertion競合は最大1回再確認し、管理変更を観測したら拒否、新しい日時は保持する。

必須lookup失敗や状態不一致は認証拒否。日時だけの保存障害はWARNと`store=FAILED`で知らせて
認証を継続する。監査障害も認証の成功を取り消さず、相関UUID付き代替WARNを試みる。
自己管理の証跡、一回消費Handoff、期待世代による保存は維持する。記録済みcontextや成功日時を
認可根拠にせず、Strategy再評価でも必須状態検査を繰り返す。

## 監査とDashboard

版付き`mfa1:` detailは標準Base64＋UTF-8 form。長さ上限16KiB、未知／重複／欠落キー、
方式とflowの不一致、時刻不一致を拒否する。Requesterは正規化の前に捨て、ユーザー／IPの既存
privacy設定を維持する。相関UUIDで従来の取込主キーを置換しない。

Dashboard索引schema 6へnullable列を追加する。認証DBの列追加は不要。
旧イベントは保持するが不足する方式情報を推測しない。旧Agentが情報を落としたイベントは
必要に応じて原本から再取り込みする。`VERIFY`と`MFA_COMPLETE`を合算しない。

## 導入と切戻し

全認証ノードの更新・旧フローの終了を確認し、Dashboard／Agentを先に更新してから機能をONにする。
既存XMLを全置換せず共通完了遷移を保持する。索引更新前に停止backupを取り、旧Dashboardへの
切戻しはbackup復元か別索引へ原本再取込みを行う。
手順は[UPGRADE.md](../UPGRADE.md#mfa-completion-recording)、
仕様は[development/MFA-SUCCESS-RECORD.md](../development/MFA-SUCCESS-RECORD.md)を参照する。

1440px／390px表示・空状態の確認も成功した。生成は別の作業場所で実施し、既存配布物は上書きしない。
