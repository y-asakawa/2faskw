# 2FAS-KW v1.3.3 GraphicalMatrixレスポンシブレイアウト 詳細設計

実装状態: 実装済み

## 1. 文書の目的

本書は、2FAS-KW v1.3.3でGraphicalMatrix認証画面のモバイル表示を設定可能にし、
連続タップ時の意図しない文字選択を抑止するための詳細設計である。

現行画面はCSS Gridを使用し、`graphicalmatrix.columns = 5`の場合は画面幅にかかわらず
5列を維持する。スマートフォンでも25画像を一画面内に収めやすい一方、狭いviewportでは
タイルが小さくなる。本改修では、指定したCSS viewport幅以下で列数を切り替えられるようにする。

本書はリリースノートを兼ねる。実装完了後、確定した設定値と導入・更新手順を
`CONFIG-REFERENCE.md`、`INSTALL.md`、`UPGRADE.md`へ反映する。

## 2. 結論

`graphicalmatrix.properties`へ次の設定を追加する。

```properties
graphicalmatrix.mobile.breakpointPx = 430
graphicalmatrix.mobile.columns = 5
```

既定値ではモバイル列数を通常列数と同じ値にするため、v1.3.2以前と表示を変えない。
4列表示を使用する環境は、次のように明示設定する。

```properties
graphicalmatrix.mobile.breakpointPx = 430
graphicalmatrix.mobile.columns = 4
```

CSS viewport幅が430px以下の場合だけ4列へ切り替える。25画像は4列7行となり、
縦スクロールを許可する。431px以上では従来どおり5列で表示する。

あわせて標準CSSでは、画像タイル、タイル画像、選択順バッジに限定して文字選択と
画像ドラッグを抑止する。既存の`touch-action: manipulation`は維持する。

```css
.tile,
.tile img,
.badge {
  -webkit-user-select: none;
  user-select: none;
  -webkit-user-drag: none;
}
```

## 3. 現行仕様

### 3.1 viewport

GraphicalMatrix認証画面と自己管理画面のHTMLテンプレートは、次を指定している。

```html
<meta name="viewport" content="width=device-width, initial-scale=1">
```

ページ側でviewport幅を固定していない。CSS viewportは端末幅とブラウザ表示状態に従う。
`maximum-scale`および`user-scalable=no`は指定せず、利用者によるピンチズームを妨げない。

### 3.2 グリッド

標準CSSは次の構造である。

```css
.grid {
  display: grid;
  grid-template-columns: repeat(var(--graphicalmatrix-columns, 5), minmax(0, 1fr));
}

.tile {
  aspect-ratio: 1 / 1;
  width: 100%;
  min-width: 0;
  touch-action: manipulation;
}
```

Javaは`graphicalmatrix.columns`をHTMLのCSS custom propertyへ設定する。

```html
<div class="grid" style="--graphicalmatrix-columns: 5;">
```

タイルは利用可能な横幅を均等に分割し、`aspect-ratio: 1 / 1`で正方形を維持する。
現行のmedia queryは余白、gap、border、badgeを縮小するが、列数は変更しない。

### 3.3 現行breakpoint

| CSS viewport幅 | 現行動作 |
| --- | --- |
| 641px以上 | 標準余白、標準gap、通常レイアウト |
| 640px以下 | 外側余白とgapを縮小し、TOTPおよびsequence変更画面を1列化 |
| 430px以下 | パネル余白、タイル余白、枠線、badgeを縮小し、操作ボタンを縦並びに変更 |
| 340px以下 | gap、タイル余白、badgeをさらに縮小 |

## 4. 設計原則

1. 既定動作を変更しない。設定追加だけで既存環境を4列化しない。
2. 認証データと表示レイアウトを分離する。列数変更は表示だけに適用する。
3. 画像ID、表示順、選択順、選択数、POST内容を変更しない。
4. 通常ログイン、現在sequence確認、新規sequence登録、強制変更で同じ列数規則を使用する。
5. CSS viewportを判定し、User-Agent文字列による端末判定は行わない。
6. JavaScriptへviewport判定を追加せず、CSS media queryで処理する。
7. ピンチズームと通常の縦スクロールを維持する。
8. `user-select: none`を`body`全体へ指定しない。説明、エラー、TOTP情報はコピー可能に保つ。
9. 不正な設定値へ黙ってフォールバックせず、設定検査を失敗させる。
10. DB、LDAP、SAML、SP metadata、MFA policyは変更しない。

## 5. 対象範囲

### 5.1 対象画面

| 画面 | テンプレートまたはfallback | モバイル列数適用 |
| --- | --- | --- |
| 通常GraphicalMatrix challenge | `views/graphicalmatrix.html` | 対象 |
| 現在sequence確認 | `views/change-current.html` | 対象 |
| 新規sequence登録 | `views/change-new.html` | 対象 |
| 強制sequence変更 | `views/change-new.html`相当 | 対象 |

| TOTP登録 | `views/totp-register.html` | 列数変更対象外 |
| MFA方式選択、完了、ロック、利用不可 | message系template | 列数変更対象外 |

### 5.2 対象外

- 画像枚数、通常列数、行数、選択数の仕様変更。
- 画像ファイルの圧縮、`srcset`、lazy load、ブラウザcache方針の変更。
- User-Agent判定、ネイティブアプリ判定、画面回転イベント処理。
- pinch zoomの禁止。
- TOTPおよびWebAuthn登録画面の機能変更。
- GraphicalMatrix照合、ロックアウト、challenge期限の変更。
- 管理API、SP管理CLI、Dashboardの変更。

## 6. 新規設定

### 6.1 Property定義

| Property | 型 | 既定値 | 許容範囲 | 説明 |
| --- | --- | --- | --- | --- |
| `graphicalmatrix.mobile.breakpointPx` | integer pixels | `430` | `240`から`1024` | モバイル列数へ切り替えるCSS viewport幅。指定値以下をモバイル表示とする。 |
| `graphicalmatrix.mobile.columns` | integer | `graphicalmatrix.columns`と同じ | `1`から`graphicalmatrix.columns` | breakpoint以下で使用する列数。通常列数と同じ場合は列数切替を行わない。 |

`graphicalmatrix.mobile.columns`の既定値は固定値`5`ではなく、読み込んだ
`graphicalmatrix.columns`とする。例えば通常列数が6の既存環境では、設定を追加しなくても
モバイル列数は6となり、表示互換性を維持する。

### 6.2 設定例

従来どおり常に5列とする。

```properties
graphicalmatrix.columns = 5
graphicalmatrix.mobile.breakpointPx = 430
graphicalmatrix.mobile.columns = 5
```

430px以下を4列にする。

```properties
graphicalmatrix.columns = 5
graphicalmatrix.mobile.breakpointPx = 430
graphicalmatrix.mobile.columns = 4
```

640px以下を4列にする。

```properties
graphicalmatrix.columns = 5
graphicalmatrix.mobile.breakpointPx = 640
graphicalmatrix.mobile.columns = 4
```

### 6.3 不正設定

次の場合は`IllegalArgumentException`とし、設定検査を失敗させる。

- 数値以外。
- `breakpointPx`が240未満または1024超過。
- `mobile.columns`が1未満。
- `mobile.columns`が通常の`graphicalmatrix.columns`を超える。

列数切替を無効化するための特別値`0`は導入しない。無効化は
`graphicalmatrix.mobile.columns`を通常列数と同じ値にして表現する。

## 7. 設定読込設計

### 7.1 GraphicalMatrixConfig

`GraphicalMatrixConfig`へ次を追加する。

```java
private static final int DEFAULT_MOBILE_BREAKPOINT_PX = 430;

private final int mobileBreakpointPx;
private final int mobileColumns;
```

読込順序は、通常列数を先に確定し、その値をモバイル列数のfallbackに使用する。

```java
final int columns = intProperty(properties,
    "graphicalmatrix.columns", DEFAULT_COLUMNS);
final int mobileBreakpointPx = intProperty(properties,
    "graphicalmatrix.mobile.breakpointPx", DEFAULT_MOBILE_BREAKPOINT_PX);
final int mobileColumns = intProperty(properties,
    "graphicalmatrix.mobile.columns", columns);
```

公開getterは次とする。

```java
public int getMobileBreakpointPx()
public int getMobileColumns()
public boolean hasResponsiveColumnOverride()
```

`hasResponsiveColumnOverride()`は次を返す。

```text
mobileColumns != columns
```

### 7.2 設定検査表示

`GraphicalMatrixConfigCheckTool`は、既存のgrid検査にモバイル設定を追加して表示する。

```text
OK: [config] grid valid: columns=5 rows=5 cells=25
OK: [config] mobile grid valid: breakpoint_px=430 columns=4 override=true
```

通常列数と同じ場合は次のように表示する。

```text
OK: [config] mobile grid valid: breakpoint_px=430 columns=5 override=false
```

## 8. CSS生成設計

### 8.1 breakpointをCSS変数にしない理由

CSS custom propertyは通常のproperty値には利用できるが、標準CSSでは
`@media (max-width: var(--breakpoint))`のようにmedia query条件へ使用できない。
そのため、breakpointをHTMLのCSS変数へ渡す方式は採用しない。

### 8.2 GraphicalMatrixAssetServlet

`GraphicalMatrixAssetServlet`は、設定されたCSSファイルを読み込んだ後、
モバイル列数が通常列数と異なる場合だけ管理CSSを末尾へ追加する。

生成例:

```css
/* 2FAS-KW managed responsive grid */
@media (max-width: 430px) {
  .grid {
    grid-template-columns: repeat(4, minmax(0, 1fr));
  }
}
```

設定値は許容範囲検査済みのintegerだけを埋め込み、任意文字列をCSSへ連結しない。
生成後のUTF-8 byte列を基準に`Content-Length`を設定する。

モバイル列数が通常列数と同じ場合は管理CSSを追加せず、既存CSSをそのまま返す。
これにより、未設定環境および独自CSS環境の表示を変えない。

### 8.3 cache

既存の`graphicalmatrix.view.css.cacheSeconds`をそのまま適用する。既定値`0`では、
設定変更後の次回CSS取得から新しいbreakpointと列数が反映される。

正のcache秒数を設定している場合、ブラウザは有効期限まで旧CSSを保持する可能性がある。
運用手順では、設定変更時にcache期限を待つか、検証用ブラウザのcacheを消去する。

### 8.4 CSPとHTML template

管理CSSは既存のCSS endpointから返すため、新しいinline `<style>`およびJavaScriptを追加しない。
HTML templateのDOM構造と既存の`--graphicalmatrix-columns`指定は変更不要とする。
テンプレート読込不能時のfallback画面も同じCSS endpointを参照するため、自動的に同じ規則が適用される。

## 9. タッチ操作と文字選択

### 9.1 touch-action

現行の次の指定を維持する。

```css
.tile {
  touch-action: manipulation;
}
```

通常の縦横panとpinch zoomを維持し、タイル上のdouble-tap zoomと二度目のtap待ちを抑える。
JavaScriptは既存の`click` eventを使用する。タイルはHTMLの`button`であるため、
EnterおよびSpaceによるkeyboard操作も維持される。

### 9.2 user-select

標準CSSへ次を追加する。

```css
.tile,
.tile img,
.badge {
  -webkit-user-select: none;
  user-select: none;
  -webkit-user-drag: none;
}
```

対象をタイル関連要素へ限定する。次は選択可能なままとする。

- 見出しと操作説明。
- エラー内容。
- 選択状態のstatus文。
- TOTP登録画面のsecretおよびcode。
- 管理者へ伝える必要があるmessage。

`-webkit-touch-callout: none`は本設計では追加しない。長押しcalloutの全面禁止は、
OSとブラウザが提供するアクセシビリティ操作まで抑制する可能性があるためである。

### 9.3 独自CSS

`graphicalmatrix.view.css`で独自CSSを指定している環境でも、モバイル列数の管理CSSは
CSS endpoint末尾に自動追加される。一方、`user-select`と`user-drag`は標準CSSの改善であるため、
独自CSSには自動追加しない。必要な環境では上記ルールを独自CSSへ統合する。

`graphicalmatrix.view.css.enabled = false`ではCSS endpoint自体を使用しないため、
モバイル列数切替も適用されない。通常列数と異なるモバイル列数を設定した状態でCSSを無効化した場合、
設定検査は適用不能として失敗させる。

## 10. 認証処理への非影響

列数切替後も、次のデータは変更しない。

| 項目 | 動作 |
| --- | --- |
| 画像ID | 既存の`displayOrder`を使用する |
| 画像枚数 | 25枚のまま |
| 選択数 | `graphicalmatrix.choice`のまま。既定4 |
| 選択順 | 既存JavaScriptの`selected`配列へ格納する |
| POST値 | comma区切りの画像ID。変更なし |
| CSRF | 既存tokenを使用する |
| challenge期限 | `graphicalmatrix.challenge.seconds`。変更なし |
| 照合 | DBまたはLDAP上のsequenceと既存方式で照合する |
| 失敗回数・ロック | 既存lockout policyを使用する |

4列表示では行末の画像位置が変わるが、サーバーへ送信する画像IDと順序は変わらない。

## 12. テスト設計

### 12.1 設定単体テスト

1. 新規property未指定時、`mobile.columns == columns`となる。
2. 通常列数5、モバイル列数4、breakpoint430を読める。
3. 通常列数6でモバイル列数未指定時、モバイル列数も6となる。
4. breakpointの240と1024を許可する。
5. breakpointの239と1025を拒否する。
6. モバイル列数0を拒否する。
7. モバイル列数が通常列数を超える場合を拒否する。
8. 数値以外と空でない不正値を拒否する。
9. CSS無効かつresponsive overrideありを拒否する。

### 12.2 CSS endpointテスト

1. overrideなしでは元CSSへ管理media ruleを追加しない。
2. 430px・4列で正しいmedia ruleを追加する。
3. 640px・4列で設定値が反映される。
4. `Content-Type: text/css;charset=UTF-8`を維持する。
5. `Content-Length`が生成後byte数と一致する。
6. `css.cacheSeconds=0`のno-cache headerを維持する。
7. 不正なCSS pathおよびCSS無効時の404を維持する。

### 12.3 ブラウザ表示テスト

次のCSS viewportで通常challengeと新規sequence登録画面を確認する。

| viewport | 期待列数 | 主な確認 |
| --- | ---: | --- |
| 320x568 | 4 | 横スクロールなし、25画像表示、縦スクロール可能 |
| 375x667 | 4 | tap選択、badge、送信・reset |
| 390x844 | 4 | 画像視認性、操作ボタン全幅 |
| 430x932 | 4 | breakpoint境界の内側 |
| 431x932 | 5 | breakpoint境界の外側 |
| 640x800 | 5 | 既存640px media queryとの共存 |
| 667x375 | 5 | landscapeで横スクロールなし |

各viewportで次を確認する。

- 画像IDの重複・欠落がない。
- 25画像がすべて表示される。
- 4画像選択後だけ送信可能になる。
- 選択解除、reset、再選択が動作する。
- 選択順badgeが正しい。
- 連続tapで文字選択表示が発生しない。
- タイル上から開始した縦スクロールが可能である。
- pinch zoomが可能である。
- keyboardのTab、Enter、Space操作が可能である。

### 12.4 認証回帰テスト

- 正しいsequenceで認証成功する。
- 誤ったsequenceで失敗回数が増える。
- 通常ロックと最大ロックの条件が変わらない。
- ordered selectionとunordered selectionの双方が動作する。
- duplicate許可・不許可の双方が動作する。
- DB保存とLDAP保存で結果が一致する。
- 自己管理の現在sequence確認と新規sequence登録が成功する。

## 13. セキュリティ評価

本改修は表示列数だけを変更し、認証秘密、画像ID、正解sequence、照合結果を追加公開しない。
JavaScriptが保持する選択情報とPOST内容も変更しない。

breakpointと列数はintegerとして範囲検査してからCSSへ出力するため、CSS injectionの入力にはしない。
User-Agentやclient申告値をサーバー側認証判定へ使用しない。viewportを偽装しても表示列数が変わるだけで、
認証結果には影響しない。

ピンチズームを禁止しないため、弱視利用者の拡大操作を維持する。`user-select: none`は
認証タイルだけに限定し、エラーや復旧情報のコピーを妨げない。

## 14. 性能評価

画像数とHTTP request数は変わらない。4列化しても25画像をすべて取得する。
CSS endpointで追加するmedia ruleは数行であり、response sizeへの影響は軽微である。

`GraphicalMatrixAssetServlet`は現在もrequestごとに設定とCSSファイルを読み込む。
本改修では、その読込済みCSSへ短い文字列を追加するだけとする。画像処理、画像resize、
server-side viewport判定は追加しない。

## 15. 更新手順案

v1.3.2から更新後、従来表示を維持する場合は新規設定を追加する必要はない。
4列表示を有効化する場合だけ、次を追加する。

```properties
graphicalmatrix.mobile.breakpointPx = 430
graphicalmatrix.mobile.columns = 4
```

設定検査後、通常challengeと自己管理画面を確認する。

```bash
sudo /opt/shibboleth-idp/bin/graphicalmatrix-plugin-check.sh \
  --idp-home /opt/shibboleth-idp \
  --config-only
```

設定とCSSはrequest時に読み込むため、設計上はproperty変更だけでJetty再起動を要求しない。
ただしPlugin JAR自体をv1.3.3へ更新した直後は、通常の更新手順どおりWAR再構築とJetty再起動を行う。

## 16. ロールバック

モバイル4列表示だけを停止する場合は、モバイル列数を通常列数と同じ値へ戻す。

```properties
graphicalmatrix.columns = 5
graphicalmatrix.mobile.columns = 5
```

または、新規2propertyを削除する。未指定時は通常列数へfallbackする。

v1.3.2 Pluginへ戻す場合、新規propertyは旧版から参照されない。ただし運用上の混乱を避けるため、
旧版へ戻す前に新規2propertyをコメントアウトする。DBおよびLDAPのrollbackは不要である。
